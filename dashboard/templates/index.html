Technical Interview Questions & Answers

Talking points and technical defenses prepared for interview panels.

Q1: Why Spark Structured Streaming over legacy Spark Streaming (DStreams)? ▼

- Event-Time Processing & Watermarking: Structured Streaming handles events based on when the transaction was executed at the terminal rather than when it arrived at the cluster.

- Unified API: Code uses the standard DataFrame/SQL API (spark.readStream instead of DStreams RDD transformations), drastically reducing maintenance complexity.

- Native Delta Lake Integration: Complete ACID compliance, exactly-once processing guarantees, and seamless time-travel auditing.

Q2: Why did you set a 5-minute watermark on stream-stream joins? ▼

- In a stream-stream join (transactions joined with fraud watchlist updates), Spark must maintain past state in memory waiting for potential matches.

- Without an explicit watermark, the state store grows indefinitely and results in cluster Out-Of-Memory (OOM) failures.

- By defining withWatermark("transaction_timestamp", "5 minutes"), Spark bounds memory state to roughly 54 MB, automatically clearing events that lag beyond the 5-minute threshold.

Q3: Explain the difference between Stream-Static join and Stream-Stream join. ▼

- Stream-Static Join: Used in high_value_transactions_alert. Silver transactions stream joins against the static customer master database. Spark performs a snapshot lookup against current customer limits without requiring state store memory or watermarks.

- Stream-Stream Join: Used in fraud_card_alert. Both transactions and watchlist files arrive dynamically. Both sides require watermarks and an inner join on card number to avoid infinite state retention.

Q4: How did you handle credential security and pipeline governance? ▼

- Databricks Secret Scopes: All Kafka credentials, PostgreSQL connection URIs, and Gmail App Passwords reside in finguard-scope, retrieved at runtime via dbutils.secrets.get() with zero plaintext credentials committed to Git.

- Unity Catalog: Full 3-level namespace (finguard.<layer>.<table>) governance with automated end-to-end data lineage.

- Lakeflow Spark Declarative Pipelines: Complete orchestration managed declaratively with automated expectations for data quality.
